This change directly contradicts the maintained spec. The spec states the allocation order is principal → interest → fees → penalties, and marks it as "a deliberate product decision, not an implementation detail." The proposed change reverses it to penalties → fees → interest → principal.

That the code compiles and existing tests pass doesn't matter here. Tests passing while behaviour inverts just means the tests don't cover this ordering, which is exactly the kind of gap a maintained behavioural spec exists to catch. The change also has real-world consequences: allocating to penalties and fees before principal keeps the borrower's principal balance higher for longer and changes what they owe, which is precisely why the order was fixed as a product decision.

DECISION: BLOCK
REASON: The proposed order (penalties, fees, interest, principal) directly inverts the spec's mandated allocation order (principal, interest, fees, penalties), which is an explicit product decision, so it must not be merged regardless of tests passing.
