# Arm: plain prose (no structured discipline — how a spec is written without tooling)

You are an engineer writing a requirements specification for this feature so that a developer
could implement it correctly. Write it in clear prose.

You may ask the stakeholder clarifying questions if you want to, then write the spec. Use your
judgement about how much to ask and what to write. Produce a specification document.

(No structured elicitation process, no ambiguity taxonomy, no forced record of open questions,
no checker. This is the baseline: a capable engineer documenting the feature as they normally
would.)
